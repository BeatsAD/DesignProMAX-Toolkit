## 2. 当前工程事实与需要修复的缺口

| 事实／缺口 | 处理方式 |
| --- | --- |
| Figma 当前是 `v0.1.0` 骨架，只有启动、选区数量通知和关闭 | 作为基础保留，后续逐项迁移，不把旧工具页面直接挂上即宣称可用 |
| 当前显示名是 `DesignProMAX — Figma` | 在实施阶段统一改为 DesignProMAX Toolkit，覆盖 manifest、UI、HTML 标题、说明和候选信息 |
| 消息只覆盖 `UI_READY`、关闭与会话状态 | 扩展请求 ID、错误码、进度、取消、资源与操作契约；不传递完整 Figma 节点 |
| UI 连接失败仅提示关闭重开，版本不匹配被静默忽略 | 显示本地化原因，提供只重试握手／读取的恢复；区分应用版本和构建标识 |
| 当前没有持久化设置及语言状态 | 建立独立存储键、版本化 schema、字段校验、超时和失败恢复，避免默认值覆盖用户配置 |
| MasterGo API 的 `imageRef`、`getImageByHref` 和 `mixed` 规则不同 | 分别适配 Figma `imageHash`、`getImageByHash`、`figma.mixed` 与文字分段 API |
| 原工具中部分页面遍历同步读取其他页 | 显式异步加载用户指定范围；只在全文件操作时考虑 `loadAllPagesAsync()` |
| 原资源协议将地图列为必需资源 | Figma 单独维护白名单、索引和往返测试，不能照抄必需地图资源的约束 |
| 尚无发布打包及自动版本流程 | 新增独立命令、版本递增、输入指纹、完整性和交付清单校验 |
| 源工程保留权利条款，未建立 Figma MIT 文件 | 在后续开源准备阶段只对有权授权的 Figma 源码应用 MIT，第三方资源维持原许可 |
| 尚无真实 Figma ID 和运行证据 | ID 在宿主验收前配置；自动检查、浏览器模拟、桌面宿主证据分别记录 |

已有记录：2026-10-16 初始骨架通过 7 项自动测试；首屏 HTML 196,499 UTF-8 字节，完整离线 HTML 同值，主线程 534 字节，17 个构建输入均在本工程。该记录不是本轮重测，也不代表工具完整版的性能。

### 3.2 启动与语言状态

1. 展示轻量英文启动壳；建立一次消息监听，完成握手。
2. 并行读取必要设置和轻量选区信息；不导出预览图、不扫描文档、不初始化全部工具。
3. 成功读取已保存语言：载入对应词条，再进入首页。
4. 成功读取且无保存值：弹出语言选择，默认英文；用户确认并保存后进入首页。
5. 存储读取失败：提示重试，不当作新安装；保存失败提示重试，或用户明确选择仅本次使用，不能伪报保存成功。
6. 页面内切换语言更新文案和 `html.lang`，不重建 UI，不丢失输入、预览、选区或任务。

语言持久化采用 `figma.clientStorage`，为插件本地设置，不承诺跨设备或跨浏览器同步。未知 locale 安全回退英文，保留其他用户设置。

### 3.3 消息、预览和执行

- 请求携带 `requestId`、消息类型及经过校验的 payload；响应明确成功／失败，错误用稳定代码和参数表达，由 UI 本地化。
- 设置读取和本地资源请求可并行并合并相同请求；画布写入使用任务控制，阻止重复点击和相互覆盖。
- 预览绑定参数、选区、页面和必要的节点／图片指纹；确认前变更使预览失效，执行时重新校验对象及权限。
- 重试握手、设置或资源读取，不自动重放业务写入；版本／构建不匹配给出明确恢复指引。
- 取消长任务时停止后续工作；已完成修改按真实结果汇报，保留可撤销边界，不承诺所有情况自动回滚。
- 异步结果不能覆盖较新的请求；离开页面或插件关闭时释放监听、Worker、Blob URL 和临时图片。
- 纯类型使用 `import type`；主线程不依赖 DOM、React 或浏览器二进制处理库。

### 3.4 Figma 适配与工具安全

- 图片：读取 `imageHash` 对应原始字节，新结果优先使用 PNG；保留或正确更新缩放、裁剪和坐标变换，不将旋转／裁剪图层误当原始像素坐标。
- 文字：识别 `figma.mixed`；写入前加载所需字体，按片段保留样式；缺字体、非法节点和不支持的复杂样式有明确反馈。
- 页面：按选定页面 `loadAsync()`；切换页面使用平台异步方法；首页不调用全文件加载。
- 尺寸适配：迁移现有结构推断和冻结规则；针对 Figma Auto layout、约束、变量绑定尺寸、组件实例及有效 min/max 重新验证，不能直接套用 MasterGo 元数据。
- 清理与拆合：保留来源对象保护与执行确认，重新检查层级、锁定和实例边界。
- 撤销：按一次用户操作组织修改；在真实宿主确认撤销范围，失败不掩盖部分成功。

## 4. 多语言与界面方案

- 所有用户可见文本进入有类型约束的词条；覆盖导航、表格、表单、工具提示、单位说明、按钮、通知、错误、空态、确认、帮助、反馈和无障碍标签。
- 主线程结果中的状态、跳过原因和错误传递代码，不把固定中文句子作为 UI 协议；图层名称和用户输入保持原文。
- 插值和复数采用明确规则，数字和日期按场景使用 `Intl`；业务输出的编号、日期格式、补零和总数规则不因界面语言偷偷改变。
- OCR 继续仅简中和英文，界面明确说明；模拟数据继续现有业务内容，不把切换日文界面误宣传为日文数据或日文 OCR。
- 首次语言选择的轻量文案和各语言名称常驻；非当前语言的完整帮助与大词条资源按需读取，不一次初始化全部语言。
- 开发期词条缺失直接报错，生产保留英文兜底；候选验收要求 8 种语言键和插值完整，兜底不作为未完成翻译的交付方式。
- 沿用现有工具流程与信息层级，适配 Figma 主题；验证亮暗主题、键盘焦点、长文本、日文／韩文换行和窗口变窄。
- 语言切换不修改用户设计稿、不会重跑填充或图片处理。翻译完整性检查与语言质量人工检查分别记录。

## 5. 资源、网络与反馈

### 5.1 离线资源

| 资源／任务 | 加载时机 | 失败处理 |
| --- | --- | --- |
| 启动、语言选择、首页、导航 | 首次 showUI | 必要初始化明确报错，已就绪 UI 不重建 |
| 当前语言功能文案、完整帮助 | 语言／页面需要时 | 当前区域重试，保留工具输入 |
| OCR Worker、WASM、简中和英文模型 | 用户主动开始 OCR | 局部加载、取消、重试和会话缓存 |
| 图片解码、像素、分割结果 | 对应工具的用户操作后 | 超限和解码错误不改原图，释放临时资源 |
| 宣传图（如沿用） | 首页提交后 | 不阻塞首页，先核对 Figma 适用文案与授权 |
| 二维码、图标库正文、地图、团队库、批量导出资源 | 不加载 | 不进入 Figma 包或资源索引 |

继续使用本地 `GET_LOCAL_RESOURCE` 分段思路，单独定义 Figma 白名单、索引版本、构建标识、读取端和测试。索引偏移与传输字符按 UTF-16 处理，体积与完整性另按 UTF-8／实际二进制计算，不能混用。

完整重组并校验后才缓存；同资源并发合并，失败不缓存坏数据，可取消和重试。空资源目录恢复必须用最新生产构建验证。Blob Worker、WASM 和任何模块加载方案均在真实 Figma 中验证；不以 CDN 或启动网络预热替代离线资源。

### 5.2 一键抠图与自定义地址

- 保留 remove.bg 与现有兼容的自定义服务协议，不默认配置用户密钥，不加入项目方计费或代理服务。
- 默认禁止上传；用户明确允许后，只在主动执行时上传预览中确认的选中图片。
- 执行前明确显示目标服务／域名、图片范围及第三方可能收费；不承诺第三方数据删除时间或免费额度。
- 密钥以本地配置保存，UI 掩码；日志、反馈导出、截图示例和仓库不包含真实密钥，不承诺本地存储强加密。
- 保留任意自定义 HTTPS 服务地址意味着正式 manifest 需要允许相应外部域名；如使用 `allowedDomains: ["*"]`，补充明确的 `reasoning` 与隐私披露。不能继续使用当前骨架的 `none` 后却宣称在线服务可用。
- 固定服务和自定义接口分别验证可访问性、CORS、鉴权、错误码、超时及取消。浏览器跨域失败给出明确说明，不静默转发到未披露代理。
- 网络白名单是平台能力声明，不等于用户上传同意；开启网络也不能使本地工具或首页产生自动请求。
- 超时／错误不替换原图；不自动重试可能产生费用的处理请求。仅在用户明确重试时发起新请求。

### 5.3 反馈与版本页

在 `src/shared/links.ts` 分别管理 `feedbackGithubUrl`、`sourceRepositoryUrl`、`xUrl`、`wechatId` 和邮箱。仓库字段允许为空；不能从个人主页推导或猜测开源仓库。

反馈页显示 X、个人 GitHub、微信号复制及邮件反馈；版本页显示正式名称、独立版本、构建标识、Figma 平台和已配置的开源仓库链接。用户点击后通过受控外链操作打开允许的 HTTPS 地址，不在启动时访问这些网站。

去掉微信二维码的 UI、图片导入、资源 ID、占位、加载重试、帮助描述及打包索引。保留原工程和其他平台本地文件，不进行批量删除。

### 6.2 版本和本地候选

- 新增 `package:plugin` 前，补齐补丁版本自动递增：同步 `package.json`、锁文件根与包项、`src/shared/constants.ts` 的 `APP_VERSION`，构建前检查一致性。
- 当前 APP_VERSION 是构建注入占位，实施时调整为递增脚本可同步维护并经构建校验的版本来源，避免只改 package 而漏改常量。
- 构建标识独立于语义版本，覆盖本次源码／构建输入，区分同版本不同构建；UI、主线程、资源和候选清单互相校验。
- 使用 Figma 独立输出与本地候选目录，不复用 MasterGo 的 `mastergo-plugin-package/`；只写明确产物，不清空目录，不混入旧文件。
- 打包清单明确 manifest、主线程、UI、所需资源和许可证；逐文件校验与最新构建一致，记录首屏、完整 HTML、主线程及总包体积。
- Figma 开发 ID 使用现有本地配置机制；真实 ID 在宿主验收前提供，不使用其他平台 ID。分发前核对正式 ID、名称和权限。

### 6.3 仓库与公开范围

用户开发完成后自行创建开源仓库；后续取得地址再补版本页及公开文档。本计划不授权创建仓库、改变可见性、推送或提交 Community。

源码分发采用明确清单，只包含 Figma 源码、配置模板、锁文件、必要资源和公开文档。不包含父工程、其他平台工程、密钥、真实配置、内部规格、协作规则、构建缓存或本地独立包。禁止上传的项目文件继续遵守原规则；不得用“开源”覆盖原有本地文件范围限制。

## 8. 测试、性能与验收矩阵

### 8.1 自动检查

| 类别 | 必测情况 |
| --- | --- |
| 工程隔离 | 源码与构建输入均在本工程；真实路径不指向父目录依赖；其他平台和根配置不变 |
| 语言 | 8 语言键／插值完整；首次默认英文；保存／读取失败；未知 locale；切换不丢状态 |
| 连接与任务 | 版本／构建不匹配、超时、重试、重复点击、并发读取、过期响应、取消与关闭 |
| 文本 | 混合字体、缺字体、锁定／隐藏文本、实例、中文标点、空输入、局部样式和执行前变更 |
| 填充规则 | 仅自定义候选，四种方式、保存失败不覆盖、旧预览失效、移除常用字段请求与资源 |
| 图片 | alpha 边界、透明空图、尺寸限制、旋转／裁剪填充、原图变更、分割边界及失败不替换 |
| OCR | 模型完整性、无网络识别、语言边界、超限、超时、取消、页面退出和 Worker 释放 |
| 页面与布局 | 未加载页、跨页范围、Auto layout、约束、有效尺寸限制、实例、冻结与重叠风险 |
| 资源 | 空目录恢复、分段顺序与长度、UTF-8／UTF-16、坏数据、并发合并、取消、重试和缓存 |
| 抠图 | 禁止上传、无密钥、服务鉴权、CORS、错误结果、超时取消、费用提示和日志脱敏 |
| 发布 | 排除资源不入包；版本一致；产物指纹；许可证清单；包与最新生产构建一致 |

保留独立 Node `*.check.mjs` 测试机制；需要 React 交互测试时在本工程增加独立测试依赖和命令，不借用父工程安装。测试验证行为与风险，不仅比较实现字符串。

运行时代码、资源或构建改动：执行类型检查、受影响功能测试、**本批最新生产构建**及启动集成测试。Figma 的测试入口继续使用本工程的 `tests/plugin-startup-integration.check.mjs`，不能拿父工程测试或旧 dist 代替。只修改文档时检查内容和差异，不打包、不递增版本。

### 8.2 性能门槛

- 实际第一次传给 `figma.showUI` 的 HTML 按 UTF-8 计量，必须严格小于 **1,572,864 字节**；不能用 gzip、源码或开发服务器替代。
- 每批记录相对上一通过构建的首屏增量、完整 HTML、主线程和总包大小，注明新增内容；不得提高阈值或跳过检查。
- 引擎、模型及大资源不在启动阶段解码；进入工具的等待单独测量，避免把慢从启动转到首次操作。
- 模块独立不等于运行时代码已分包；页面代码增长超预算时先减少依赖、提取轻量函数，再验证 Figma 可用的加载方案。

### 8.3 真实宿主验收

在相同机器、文档、账号和版本条件下，分别记录桌面端与网页端结果：

- 首次启动：客户端重启后首次打开至少 3 组；重复打开至少 5 次，保存逐次数据，不用平均数掩盖失败。
- 分段：用户菜单操作、主线程入口、showUI、首页提交、可操作状态；记录测量方式和可观测边界。
- 10 工具正常路径、失败路径、取消和撤销；空选区、多选、大文件、多页和实例场景。
- 首次语言选择、8 语言主要页面、长文案和亮暗主题；语言质量未人工复核时明确标识。
- 离线状态下本地工具正常，抠图给出明确网络提示；反馈外链和微信／邮箱复制正确。
- 不将 UI_READY、绘制机会、首屏体积下降、浏览器模拟或包校验称为真实冷启动加速。
