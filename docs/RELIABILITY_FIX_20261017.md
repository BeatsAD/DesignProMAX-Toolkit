# Figma v0.3.2 可靠性修复与验收

日期：2026-10-17。范围：本轮功能审查中的 F1–F7、R1–R2，以及原生验证发现的撤销边界和自动布局关联移动问题。未发布 Community、提交或推送 Git。

## 修复结果

| 问题 | 实施 | 主要回归证据 |
| --- | --- | --- |
| F1：未加载页面使当前页写入失败 | ID 查找优先使用 Figma `getNodeByIdAsync`；兼容宿主先查当前页；统计只加载请求页面 | 前置未加载页面抛错时，当前选中文本仍可写入；统计限定页列表 |
| F2：取消后字体等待完成仍写入 | 所有字体等待后再检查取消、目标和选区；写请求取消后等待最终回执；分批操作返回已完成数量 | 合并、拆分、替换的字体等待取消无写入；批量填充保留前项成功数；原生桥取消与超时用例 |
| F3：合并删除中途失败丢字 | 短同步写入使用独立撤销步骤；失败先提交本次步骤再撤销；缺少原生恢复时保留完整合并内容并返回状态待核对 | 故障注入恢复 A/B/C 及前一步位置；无原生恢复报告 `WRITE_STATE_UNKNOWN`；拆分失败移除本次克隆 |
| F4：等待期间覆盖修改或锁定的节点 | 预览保存目标值快照；写前及异步等待后核对内容、样式、几何、祖先锁定和选区；不再扫描整份文档生成签名 | 修改、锁定、删除和换选区用例均无覆盖 |
| F5：成功回执被选区刷新错误吞掉 | 写入结果与刷新分开；刷新失败提供独立重试入口；同次读取合并；离开页面后的旧结果不覆盖新任务 | 实际 hook 在写入成功、选区读取失败时仍返回成功结果；桥接取消保留回执 |
| F6：替换内容的美元序列被解释 | 普通字符串替换使用回调返回用户原文 | `$&`、`$$`、反引号、单引号、`$1`、中文价格等字面替换；同节点多个区间从右向左写入 |
| F7：清理实例内部条目错误默认勾选 | 默认扫描排除实例子项；包含实例时仅预览，禁用勾选；普通条目仍可执行 | 默认排除和混合预览的普通条目清理 |
| R1：多图后项失败残留前项 | 预检所有输出；短同步事务统一恢复；跟踪创建后尚未赋值的节点 | 第二张图 resize 失败后无新增图层残留 |
| R2：其他读取刷新来源后授权旧结果 | 每次读取生成绑定来源和工具的会话令牌；OCR 不刷新写入授权；完成回执去重，相同在途请求合并；结果不明确时禁止同操作盲重放 | 几何变化后重新 OCR 读取仍拒绝旧结果；重复写入只有一个图层；跨工具/缺失令牌拒绝；未知结果重放拒绝 |

来源缓存只保存元数据，不复制整份图片字节；最多 128 个来源，每个最多 64 个完成或未知操作。过期或超出上限的来源需重新读取。

原生回归还发现：自动布局会在本次文本写入后同步移动其他目标。现在先核对同一布局中受影响目标，再同步写入并更新对应快照；中间不允许异步等待。因此不会把自身引起的移动误判为外部修改，也不会接受字体等待期间的协作者编辑。

## 自动检查

`npm run verify`：类型检查、最新生产构建、八语词条覆盖、110 项测试、1688 个构建输入隔离全部通过。另显式执行 `node --test tests/plugin-startup-integration.check.mjs`，对本次生产主线程实际传给 `figma.showUI` 的 HTML 及资源往返校验。

新增 `tests/reliability.check.mjs` 26 项行为回归；原生桥增加 2 项；原有图片写入测试同步传入来源令牌。外部抠图测试使用当前 `src/reference/ui/remove-bg.ts` 实现，模拟请求，覆盖未授权、缺少密钥、脱敏占位、401/402/403/429/500、密钥脱敏、自定义服务、取消和超时；不调用付费服务。

本机日志及回执位于 `output/reliability-fix-20261017/`。旧审查复现脚本仍作为历史证据保留，其断言针对旧缺陷，不能作为修复后通过标准。

浏览器实际操作确认：自定义字段生成 3 项预览，确认写入成功 3 个、失败 0 个，美元序列保留原文；撤销恢复原值，并只删除本次创建的测试字段。透明样例从 480×240 裁为 336×152，写入 1 项、失败 0 项。浏览器 Space 64 已关闭，回执 `output/reliability-fix-20261017/browser-receipt.json`。这部分只证明浏览器示例宿主。

选区刷新失败的重试在常规窗口显示独立提示，在紧凑窗口进入顶部操作栏，使既有高度测量包含该入口。

## 原生 Figma 证据

仅在独立 Draft 文件 `DesignProMAX · Reliability QA 2026-10-17` 内生成 QA 内容；未操作用户原有设计文件。

- 在真实插件执行上下文中运行同步恢复探针：合并式写入并删除第二个来源后注入错误，A/B/C 完整恢复，前一步 `x=17` 保留；连续正常写入 First/Second 后，单次撤销恢复 First。
- 12 项针对性检查通过：文本填充、美元字面区间替换、文本合并、拆分、清理、尺寸适配、统计、裁剪写入及重复回执、图片分割写入、抠图结果写入、OCR 来源读取、自动布局多文本填充。
- 原生 UI 点击“开始识别”，离线引擎、WASM、模型加载并完成识别。紧贴文字边界的样例 `Hello Toolkit 2026` 输出 `Hello Toolkit 70276`；运行链路通过，数字识别存在误差，需要人工核对，不能视为准确率验收。
- 临时故障注入和功能探针只保留在本机 output。最终 dist 与注册 code.js 已恢复为不含探针的正式构建；真实设置页显示 v0.3.2，关闭重开进入首页。
- 开发入口统一为本工程 `DesignProMAX Toolkit/manifest.json` 的实际路径；旧 Documents 路径的重复注册记录已移除，目录链接与本机文件保留。移除旧入口后一次“运行上次插件”指向旧缓存失败，随后从 Development 中明确选择保留入口正常运行。

这些是有明确样例与断言的原生检查，不等于所有工具参数、复杂文档或全量端到端验收。图片分割的自动识别算法、透明裁剪像素算法另由自动测试及浏览器样例覆盖；原生检查主要确认真实图片写入和坐标 API 可用。
